david_igou.rustfs.user module – Manage IAM users on a RustFS server

Note

This module is part of the david_igou.rustfs collection (version 2.0.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install david_igou.rustfs. You need further requirements to be able to use this module, see Requirements for details.

To use it in a playbook, specify: david_igou.rustfs.user.

New in david_igou.rustfs 2.0.0

Synopsis

  • Create, remove, enable/disable IAM users via the RustFS admin REST API.

  • An existing user’s secret is never touched unless update_secret=true - on RustFS, re-adding an existing access key rotates its secret in place, so rotation is a deliberate act, not a converge side effect.

  • The module never generates credentials, the secret arrives resolved from the caller.

Requirements

The below requirements are needed on the host that executes this module.

  • botocore

Parameters

Parameter

Comments

access_key

string / required

Access key the module authenticates with.

For admin-plane modules this must be an admin/root credential.

ca_bundle

path

Path to a CA bundle used to verify the endpoint’s TLS certificate, for private-CA deployments.

endpoint

string / required

URL of the RustFS server, for example https://nas.example.net:20292.

Plain http:// endpoints are accepted for dev/test instances.

name

string / required

The user’s access key (RustFS identifies users by access key).

region

string

Region used for AWS SigV4 request signing.

RustFS accepts the default on single-node deployments; change it only if the server was deployed with a different region identity.

Default: "us-east-1"

retries

integer

Total attempts for each API call.

Only transport-level failures (connection refused/reset, timeouts, HTTP 502/503/504) are retried - the RustFS admin API is known to refuse connections in bursts while the S3 data path stays healthy.

Permanent errors (authentication, not-found, conflict, validation) fail immediately.

Default: 8

retry_delay

integer

Seconds to sleep between retry attempts.

Default: 3

secret

string

The user’s secret key.

Required to create a user, ignored for an existing user unless update_secret=true.

secret_key

string / required

Secret key paired with access_key.

state

string

Whether the user should exist.

Choices:

  • "present" ← (default)

  • "absent"

status

string

Whether the user account is enabled or disabled.

When omitted, the status of an existing user is left unmanaged (new users are created enabled).

Choices:

  • "enabled"

  • "disabled"

update_secret

boolean

Rotate the secret of an existing user to secret.

The module cannot read secrets back, so with this option the module always reports a change when the user exists.

Choices:

  • false ← (default)

  • true

validate_certs

boolean

Whether to validate TLS certificates of the endpoint.

Only affects https:// endpoints.

Choices:

  • false

  • true ← (default)

Notes

Note

  • All requests are signed with AWS SigV4 (service s3) - both the S3 data plane and the RustFS admin REST API under /rustfs/admin/v3.

  • Every connection option can also be provided via environment variables of the module’s process - RUSTFS_ENDPOINT, RUSTFS_ACCESS_KEY, RUSTFS_SECRET_KEY, RUSTFS_REGION, RUSTFS_VALIDATE_CERTS, RUSTFS_CA_BUNDLE, RUSTFS_RETRIES, RUSTFS_RETRY_DELAY - for example through the environment keyword on a block or play.

Examples

- name: Create an application user
  david_igou.rustfs.user:
    endpoint: https://nas.example.net:20292
    access_key: admin
    secret_key: EXAMPLEadminsecret
    name: app-backups
    secret: EXAMPLEusersecret

- name: Disable a user without touching its secret
  david_igou.rustfs.user:
    endpoint: https://nas.example.net:20292
    access_key: admin
    secret_key: EXAMPLEadminsecret
    name: app-backups
    status: disabled

- name: Remove a user
  david_igou.rustfs.user:
    endpoint: https://nas.example.net:20292
    access_key: admin
    secret_key: EXAMPLEadminsecret
    name: app-backups
    state: absent
