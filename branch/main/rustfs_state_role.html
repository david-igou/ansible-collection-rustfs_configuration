david_igou.rustfs.rustfs_state role – Reconcile one RustFS instance’s in-server state against a declarative spec

Note

This role is part of the david_igou.rustfs collection (version 2.0.0).

It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it use: ansible-galaxy collection install david_igou.rustfs.

To use it in a playbook, specify: david_igou.rustfs.rustfs_state.

Entry point main – Reconcile one RustFS instance’s in-server state against a declarative spec

Synopsis

  • Reconciles IAM policies, buckets, versioning, lifecycle rules, users and policy attachments on the RustFS instance this host represents (a connection-local stub named after the instance; the role reaches rustfs_state_endpoint through the collection’s modules — direct S3 and admin-API calls, no rc CLI), and verifies that the provided per-user credentials actually authenticate.

  • The role is a pure function over its inputs. Every credential arrives as a resolved value — the role performs no secret lookups; secret-store lookup expressions belong in the caller’s data (host_vars).

  • Run with --check for drift-detection mode (reads execute, mutations do not, and the play fails on any drift or dead credential).

Parameters

Parameter

Comments

rustfs_state_admin_access_key

string / required

Resolved admin/root access key.

Secret-adjacent — supply via your secret store. The modules the role calls never print it.

rustfs_state_admin_secret_key

string / required

Resolved admin/root secret key. Secret — supply via your secret store; the modules mark it no_log everywhere it flows.

rustfs_state_buckets

list / elements=dictionary

Managed buckets.

Default: []

lifecycle

dictionary

Lifecycle configuration. Omit to leave unmanaged.

rules

list / elements=dictionary / required

Lifecycle rules in the standard S3 API shape (PascalCase keys — Status, Prefix, Expiration, …), as any S3 tool documents them. An ID is optional; rules without one get a deterministic generated ID. An empty list is rejected (the role never deletes) — omit lifecycle to leave rules unmanaged.

To scope a rule to a path, use a top-level Prefix key (for example Prefix of logs/) — the shape proven live. A nested Filter round-trips over the S3 API, but whether the beta-8 expiry scanner honours it at execution time is unverified. An empty prefix (whole bucket) may be omitted.

Two whole-bucket retention shapes cover most needs. Expire CURRENT objects N days after creation (typical for a non-versioned bucket — logs, cluster backups):

- Status: Enabled

Expiration:

Days: 30

Expire NONCURRENT versions N days after they become noncurrent (a versioned bucket — keeps the live object, prunes old versions):

- Status: Enabled

NoncurrentVersionExpiration:

NoncurrentDays: 30

name

string / required

Bucket name.

versioning

boolean

Desired versioning state. Omit (or set null) to leave unmanaged.

Choices:

  • false

  • true

rustfs_state_builtin_policies

list / elements=string

Server-shipped policies never reported as unmanaged.

Default: ["readonly", "readwrite", "writeonly", "diagnostics", "consoleAdmin"]

rustfs_state_ca_bundle

string

Path to a CA bundle for private-CA endpoints. Empty uses the system trust store.

Default: ""

rustfs_state_endpoint

string / required

Base URL of the instance (https://host:port). http:// is also accepted for a plain-HTTP dev/test instance.

rustfs_state_fail_on_drift

boolean

Fail the play when any change is (or would be) made. Defaults to the check-mode flag, which makes --check the drift-detection mode.

Choices:

  • false

  • true

rustfs_state_fail_on_unmanaged

boolean

Escalate unmanaged server-side resources from a report to a failure. Nothing is ever deleted either way.

Choices:

  • false ← (default)

  • true

rustfs_state_ignore_unmanaged

list / elements=string

Allowlist of report entries (without the hostname prefix) excluded from the unmanaged report and gate.

Shapes are <kind>:<name> (for example bucket:scratch) and, for out-of-band policy attachments — which the role never detaches — the exact user:<name>:extra-attachment:<policy[+policy...]> entry as reported.

Default: []

rustfs_state_policies

list / elements=dictionary

Managed IAM policies.

Default: []

document

dictionary / required

IAM policy document (free-form dict). Write it the natural way — a Version plus a Statement list of Effect/Action/Resource entries; no document-level ID or per-statement Sid/Condition boilerplate is needed. The server injects those empties on store and the canonical comparison absorbs them (along with array ordering), so a from-scratch document converges to steady state.

Minimal example:

Version: “2012-10-17”

Statement:

- Effect: Allow

Action: [s3:GetObject, s3:PutObject, s3:ListBucket]

Resource: [arn:aws:s3:::app-data, arn:aws:s3:::app-data/*]

name

string / required

Policy name.

rustfs_state_retries

integer

Total attempts per API call; only transport-level failures retry (connection refused/reset, timeouts, HTTP 502/503/504).

Default: 8

rustfs_state_retry_delay

integer

Delay in seconds between retries.

Default: 3

rustfs_state_tls_insecure

boolean

Allow insecure TLS (self-signed certificate without a CA bundle). TLS-only — a no-op for http:// endpoints.

Choices:

  • false ← (default)

  • true

rustfs_state_users

list / elements=dictionary

Managed IAM users; a user’s name is its access key.

Every entry’s policies list is pre-asserted against managed plus builtin policy names, so a typo fails fast with a clear message.

Default: []

access_key

string

Access key to use for the liveness check, as stored in the credential store (defaults to name). A mismatch with the server identity is exactly what liveness detects.

liveness_bucket

string

Bucket to list with the provided credentials each run; enables the credential-liveness check.

name

string / required

Access key (identity) of the user on the server.

policies

list / elements=string

Policy names to attach (add-only; the role never detaches — extras are reported as unmanaged).

Default: []

secret_key

string

Resolved secret key. Required when the user may need to be created and for the liveness check. Never rewritten for an existing user. Secret — supply via your secret store; the modules mark it no_log everywhere it flows.
